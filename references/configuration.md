# Конфигурация

Конфигурацию готовит и передаёт администратор отдельным приватным env-файлом. По умолчанию пакет ищет его в `~/.codex/secrets/papa-shin-stock.env`; другой путь можно указать переменной процесса `PAPA_SHIN_STOCK_CONFIG`.

Поддерживаемые имена параметров:

| Имя | Назначение |
|---|---|
| `PAPA_SHIN_STOCK_MANIFEST_URL` | Абсолютный HTTPS-адрес машинного манифеста без userinfo |
| `PAPA_SHIN_STOCK_USERNAME` | Имя учётной записи только для чтения |
| `PAPA_SHIN_STOCK_PASSWORD` | Секрет учётной записи только для чтения |
| `PAPA_SHIN_STOCK_PRODUCT_ID_FIELD` | Поле связи товара |
| `PAPA_SHIN_STOCK_OFFER_PRODUCT_ID_FIELD` | Поле связи предложения с товаром |
| `PAPA_SHIN_STOCK_CACHE_DIR` | Необязательный абсолютный путь к отдельному leaf-каталогу локального кэша вне каталога skill package |

Не придумывай значения и не запрашивай их в чате. Не печатай содержимое файла, не передавай его в аргументах команд и не сохраняй в репозитории. Отсутствующий файл возвращает безопасный код `config_missing`; повреждённый или нечитаемый файл — `config_invalid`. В обоих случаях попроси администратора проверить готовый приватный файл, не раскрывая его путь.

Парсер читает только буквальные строки `KEY=VALUE`: файл не исполняется как shell-код и не выполняет подстановки.

Путь кэша должен указывать на отдельный узкий leaf-каталог. Корень файловой системы или диска, домашний каталог, сам skill package, их предки и вложенные в skill каталоги отклоняются. При первом запуске пакет принимает только отсутствующий либо действительно пустой leaf-каталог. Он создаёт служебный marker `.papa-shin-stock-cache-root.json` напрямую с exclusive-create и только после строгой проверки считает каталог принадлежащим этому пакету. Непустой каталог без marker, повреждённый, oversized, ссылочный или подменённый marker отклоняется без удаления и автоматического принятия содержимого.

Если первичная запись или синхронизация marker прервалась, пакет откатывает только marker с подтверждённой identity через удерживаемый parent handle. Если точное владение доказать нельзя, он сохраняет объект и завершает работу fail-closed: canonical path не удаляется по повторно разрешённому имени, а непустой unmarked root повторно не принимается. Поскольку кэш воспроизводим, для неоднозначного состояния укажите новый отсутствующий или пустой leaf-каталог и выполните штатное обновление; очистка либо восстановление старого каталога допустимы только как отдельная offline maintenance при остановленных процессах.

На POSIX-системах после attestation пакет проверяет корень кэша с mode `0700`, marker и остальные файлы — с mode `0600`; существующие обычные artifacts ужесточаются через уже открытый file descriptor, symlink и non-regular paths отклоняются. Создание кэша в group/world-writable parent без sticky bit отклоняется fail-closed.

Для нативного Windows весь cache workflow использует изолированный Win32 handle backend: root/marker attestation, lock publication и release, staging, потоковую загрузку, checksum verification, atomic activation, `current.json`, runtime status и cleanup. Дочерние объекты открываются относительно удерживаемого parent handle; backend проверяет `FILE_ID_INFO`, тип объекта, reparse attributes, link count и final path, а rename/disposition выполняет через `SetFileInformationByHandle` с последующим flush родителя. Pointer обновляется через payload CAS; post-publication failure пытается тем же CAS восстановить предыдущий pointer и никогда не удаляет active или неаттестованный foreign объект.

Win32 policy, race и fault-сценарии покрыты mock-тестами, запускаемыми на macOS/Linux; отдельный native integration test выполняет два реальных refresh в Windows Server 2022 с Python 3.11/3.12. Mock-тесты и локальный прогон на другой ОС не являются native Windows proof: для конкретного commit проверяйте зелёный Windows CI. Выделенный cache leaf должен находиться в профиле текущего пользователя и иметь ограничивающий чтение и запись ACL; пакет не создаёт и не аттестует DACL самостоятельно.

Ownership marker защищает выделенный root от случайного выбора чужого каталога и подмены между проверками, но не является секретом и не изолирует от другого процесса с тем же системным пользователем. Не запускайте недоверенный код под той же учётной записью и не записывайте посторонние файлы в marked cache root.

Legacy-кэш без marker автоматически не принимается. Поскольку кэш воспроизводим, для миграции укажите новый отсутствующий или пустой leaf-каталог в `PAPA_SHIN_STOCK_CACHE_DIR` и запустите штатное обновление заново. Старый каталог не переименовывайте и не удаляйте во время работающего refresh; его отдельная очистка относится к доверенному offline maintenance.

На POSIX, если установка refresh lock прервалась уже после публикации canonical lock, пакет перемещает подтверждённый lock в новый уникальный `.refresh.lock.abort-*` quarantine. Такой exceptional artifact не удаляется автоматически, поэтому его допустимо разбирать только во время quiescent/offline maintenance после проверки точного каталога и отсутствия активного refresh.

На Windows release и stale reclaim перемещают только identity-bound lock в уникальный `.refresh.lock.release-*` или `.refresh.lock.reclaim-*`. Пакет выполняет bounded recovery не более чем для 64 известных artifacts и сверяет exact inventory, owner payload и heartbeat timestamp до удаления. Обычный release не оставляет lock artifacts; неустранимый безопасным способом artifact сохраняется, а результат получает `cache_cleanup_incomplete`. Foreign или изменённый quarantine автоматически не удаляется.

Файлы поколения разрешено загружать только по HTTPS с того же origin, что и manifest. Каждый сетевой запрос использует конечный socket timeout 30 секунд. Размер manifest ограничен 1 MiB, а каждый заявленный файл поколения — 16 GiB; первый байт сверх заявленного размера немедленно прерывает загрузку. `401` и `403` возвращают `auth_failed`, остальные сетевые и HTTP-сбои — `network_error`; приватные URL и тела ответов в сообщения не включаются.
